# nodit 리브랜딩 및 조회 최적화

## 범위와 완료 조건

- 월간 캘린더는 PC와 모바일 모두 각 날짜의 일정을 생략 없이 표시하고 내용에 따라 늘어난다.
- 브랜드는 nodit. / 노딧(Node + Do it), 펜 아이콘, 골드 계열로 통일한다.
- 같은 달 날짜 선택은 추가 서버 요청 없이 처리하며 URL과 뒤로가기를 유지한다.
- 인증·소유권·저장 실패 처리·사진 비공개 접근을 유지한다.
- 실제 운영 DB 대신 지연을 넣은 모의 Supabase로 조회 횟수와 동작을 검증한다. 운영 지연 자체의 개선 수치는 별도로 측정하기 전까지 단정하지 않는다.

## 정리 계획

1. 기존 테스트(23개)로 비밀번호, 세션 폐기, 소유권, 완료·사진, 퀴즈 동작을 보호한다.
2. 모의 Supabase를 연결한 프로덕션 HTTP 검사로 변경 전 조회 횟수를 기록한다.
3. 요청 단위 세션 조회를 중복 제거한다. 사용자 데이터를 요청 간 공유 캐시에 저장하지 않는다.
4. 월간 데이터에서 날짜를 브라우저에서 선택하고 전체 일정을 표시한다. 숨김·더 보기용 코드와 스타일을 제거한다.
5. 사진 URL 발급은 인증된 사진 경로를 열 때 수행한다. 월간 페이지에서 사진별 선행 요청을 제거한다.
6. 학습 목록은 본인의 완료된 curriculum_id만 조회한다. 저장 후 이중 refresh를 제거하고 관련 경로만 무효화한다.
7. 보이는 데이터 화면만 주기적으로 갱신하고 퀴즈 중·숨긴 탭의 불필요한 조회를 중단한다. 실제 페이지 이동에는 로딩 상태를 제공한다.
8. DESIGN.md의 브랜드·반응형 규칙에 맞춰 스타일과 아이콘을 변경한다.
9. 테스트, lint, typecheck, build, 모의 HTTP 검사, 가능한 브라우저 검증을 수행한다.

## 보존할 오류 처리

- 로컬 SQLite와 Supabase의 두 저장 경로는 배포 환경에 따른 명시적 호환 경로다. Vercel에서 로컬 저장을 거부하는 보호를 유지한다.
- client-actions의 네트워크 오류 변환은 입력을 보존하는 사용자 안내다. 서버의 권한 검사와 오류를 성공으로 바꾸지 않는다.
- 사진 교체 후 이전 파일 삭제 실패는 이미 저장된 새 사진을 취소하지 않고 서버에 기록하는 정리 경로다. 유지한다.

## 측정 결과

환경: 같은 프로덕션 Next.js 빌드 방식, 운영 DB 대신 요청마다 30ms 지연을 넣은 모의 Supabase. 일정 8개 중 한 날짜에 7개, 사진 4개를 배치했다.

| 항목                       | 변경 전             | 변경 후                             |
| -------------------------- | ------------------- | ----------------------------------- |
| 캘린더 최초 외부 요청      | 7회                 | 2회                                 |
| 캘린더 내 세션 조회        | 2회                 | 1회                                 |
| 최초 사진 서명 요청        | 4회                 | 0회; 사진을 열 때 1회               |
| 캘린더에 표시된 일정       | 3개 (+n 생략)       | 8개 전부                            |
| 학습 목록 외부 요청        | 3회, 전체 일정 조회 | 2회, 본인 완료 curriculum_id만 조회 |
| 같은 달 날짜 선택·뒤로가기 | 서버 내비게이션     | 브라우저·DB 요청 모두 0회           |

- `npm test`: 25개 통과. 기존 권한·세션·학습·퀴즈에 완료 이력 필터·중복 제거 검증을 추가했다.
- `npm run build`: 통과.
- `node scripts/check-performance.mjs --browser`: 프로덕션 HTTP 검사와 실제 Chrome 검사 통과.
- HTTP: 미로그인 페이지 접근 차단, 요청당 세션 조회 1회, 다음 요청에서 폐기 세션 차단, 사진 미로그인 401·잘못된 키 404·유효한 키만 비공개 서명 리다이렉트.
- Chrome: PC 1440px, 모바일 360/390px에서 전체 일정 표시와 가로 넘침 없음. 날짜/뒤로가기 추가 요청 0회, 구성원 필터, 완료 저장·실패 시 복구, 일정·공유 글 저장 후 목록 갱신, 캘린더 저장 후 중복 GET 없음, 퀴즈 A-1+A-2 103문항 시작과 4지선다, 로그인 화면을 확인했다.
- 추가 의존성이나 DB 스키마 변경은 없다. 기존 세션과 구성원 색상 식별자는 유지한다.

Chrome 검사는 `npm run test:performance -- --browser`로 실행한다. 기본 경로는 macOS의 Google Chrome이며 다른 환경은 `CHROME_PATH`로 실행 파일을 지정한다. 임시 프로필은 종료 시 제거하고 스크린샷은 시스템 임시 폴더의 `nodit-qa`에 저장한다.

이 결과는 요청 수 감소와 동작 검증이다. 운영 Vercel↔Supabase의 실제 응답 시간, 무료 인스턴스 기동 지연, 리전 간 네트워크 시간까지 개선했다고 단정하지 않는다. Vercel 함수와 Supabase의 실제 리전 확인은 운영 후속 점검이다.
