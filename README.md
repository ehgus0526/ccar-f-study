# 노딧 nodit. · CCAR-F Study

CCAR-F 단기 스터디를 위한 Next.js 웹서비스입니다.

nodit.은 Node + Do it을 뜻합니다. 골드 테마와 펜 아이콘을 사용합니다.

## 구현한 기능

- 이름 + **yymmdd 여섯 자리** 로그인, 30일 세션, DB 기반 로그인 시도 제한
- 구성원 필터가 있는 공유 월간 캘린더와 날짜별 학습 목록. PC·모바일 모두 날짜별 전체 일정을 표시하고 내용에 따라 높이가 늘어납니다.
- 자유 일정과 영상 4개·워크북 18개·영단어 4묶음에서 일정 등록
- 여러 날짜에 같은 학습을 일괄 등록, 날짜별 개별 완료·수정·삭제
- 선택 학습 메모와 인증 사진 1장, 사진 자동 압축·교체·삭제
- 짧은 글과 외부 링크, 이미지 1장을 공유하는 공유함. 이미지는 미리보기·교체·삭제를 지원합니다. 게시글별 댓글은 오래된순이며 작성자만 수정·삭제할 수 있습니다.
- 영단어 퀴즈: A-1~A-4 다중 선택, 200개 단어 중 선택 묶음 전체 무작위 출제, 4지선다·정답 확인, 결과와 틀린 단어 반복 복습
- 작성자만 변경 가능한 권한 검사, 모바일 하단 내비게이션
- CCAR-F LMS 바로가기, 활성 데이터 화면에서 60초 간격 및 탭 복귀 시 기록 갱신. 숨긴 탭과 퀴즈 화면은 자동 조회하지 않습니다.

## 로컬 실행

Node.js 24가 필요합니다. 날짜는 한국 시간, 시간 지정 없는 하루 단위입니다.

```sh
npm ci
npm run setup:members
npm run dev
```

`http://localhost:3000`에 접속합니다. 계정 이름은 도현, 예은, 지은입니다. 계정 초기화 시 각자의 생년월일을 **yymmdd** 형식으로 입력합니다. 이 작업 환경에는 전달받은 값의 해시로 세 계정을 이미 초기화했습니다.

`.env.local`에는 비밀번호 해시와 환경별 연결 설정이 들어가며 Git에서 제외됩니다. 실제 일정·글은 `.data/study.sqlite`, 사진은 `.data/photos`에 저장됩니다. 로컬 서버를 끄더라도 데이터는 유지됩니다. 같은 서버에 접속하는 브라우저는 같은 기록을 봅니다. 다른 기기에서 접근하려면 개발 PC의 네트워크 주소와 3000번 포트를 사용합니다.

`.env.local`, `.data`는 저장소에 올리지 마세요. 실제 계정 원문이나 해시를 로그에 출력하지 않습니다.

## Supabase와 Vercel 운영 배포

운영 환경은 Supabase를 저장소로 사용하고 Next.js 앱은 Vercel에 배포합니다. 다음 절차로 연결합니다.

1. 전용 Supabase 프로젝트에 `supabase/schema.sql`을 적용합니다. 테이블, 인덱스, 비공개 사진 버킷이 생성됩니다. 앱은 Next.js에서 인증·권한을 검사하고 서버 전용 키로 접근합니다. `anon`·`authenticated` 역할에는 테이블 접근을 허용하지 않습니다.
2. `.env.local`에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 설정합니다. 비밀 키에 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.
3. `npm run setup:supabase -- --migrate-local`을 실행합니다. 세 계정의 해시와 기존 로컬 일정·공유 글·사진을 이전하고 `STUDY_STORAGE=supabase`로 바꿉니다. 로컬 세션은 이전하지 않으므로 다시 로그인해야 합니다. 로컬 기록이 필요 없으면 `--migrate-local`을 생략합니다. 이전은 ID 기준 upsert이므로 반복 실행할 수 있습니다.
4. Vercel에 이 Next.js 저장소를 연결하고 Node.js 24와 다음 서버 환경변수를 설정합니다.

| 변수                  | 값                      |
| --------------------- | ----------------------- |
| `STUDY_STORAGE`       | `supabase`              |
| `SUPABASE_URL`        | 프로젝트 HTTPS URL      |
| `SUPABASE_SECRET_KEY` | 서버 전용 secret key    |
| `LOGIN_HASH_SECRET`   | 충분히 긴 무작위 문자열 |

계정 등록 후 운영 서버에는 `STUDY_PASSWORD_HASHES`가 필요하지 않습니다. 로컬 `.env.local`을 통째로 복사하지 않고 위 변수만 등록합니다. Vercel에서는 로컬 파일 DB 사용을 거부하여 임시 파일시스템에 데이터가 유실되지 않게 합니다. 방문자가 Vercel 계정으로 별도 로그인해야 하는 배포 보호 설정은 사용 목적에 맞게 확인합니다.

5. 배포한 HTTPS 주소에서 세 계정 로그인, 서로의 일정 열람, 본인만 수정, 사진 인증을 확인합니다. 사진은 JPEG·PNG·WebP를 지원하며 브라우저에서 긴 변 1600px 이하·2MB 이하 JPEG로 변환됩니다. 인증 사진은 공개 URL로 저장하지 않고 1시간 유효한 서명 URL로 보여줍니다.

### 기존 운영 DB에 댓글 기능 추가

배포 전에 Supabase SQL Editor에서 `supabase/migrations/20261105000100_shared_comments.sql`을 실행합니다. 기존 데이터는 유지하고 댓글 테이블·인덱스·서버 전용 접근 권한을 추가합니다. 새 프로젝트는 업데이트된 `supabase/schema.sql` 전체를 적용하면 됩니다. 게시글을 삭제하면 해당 댓글도 DB에서 함께 삭제됩니다. 로컬 SQLite는 서버 시작 시 댓글 테이블을 자동 생성하며, 로컬 → Supabase 이전에는 댓글도 포함됩니다.

### 기존 운영 DB에 공유 글 이미지 추가

배포 전에 SQL Editor의 새 쿼리에서 `supabase/migrations/20261105000200_shared_post_photos.sql`을 실행합니다. `shared_posts`에 선택 이미지의 저장 경로를 담는 `photo_key` 컬럼만 추가하므로 기존 글과 댓글은 유지됩니다. 새 프로젝트는 최신 `schema.sql`을 적용하면 두 마이그레이션을 별도로 실행할 필요가 없습니다.

공유 글에는 JPEG·PNG·WebP 이미지 1장(최대 2MB)을 첨부합니다. 기존 비공개 `proofs` 버킷을 재사용하고 로그인한 구성원에게만 이미지를 제공합니다. 작성·수정 중 미리보기를 제공하며, 이미지 교체·삭제는 글을 저장하면 반영됩니다. 실패 시 입력과 선택 파일을 보존합니다. 글 삭제 시 댓글과 이미지도 삭제합니다. SQLite는 기존 글을 보존하며 컬럼을 자동 추가하고, 로컬 → Supabase 이전에는 공유 글의 이미지도 포함됩니다.

## 검증

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

테스트는 임시 DB를 사용하며 실제 `.data`에 접근하지 않습니다. 비밀번호 형식, 한국 시간 경계, 다중 날짜 원자적 등록·재전송, 소유권, 완료 취소, 세션 만료·폐기, 로그인 실패 기록, 외부 링크, 사진 파일 검증을 확인합니다. 브라우저 UI 검증에 사용하는 `[검증용]` 기록은 사용자 기록과 구분하고 완료 후 정리합니다.

프로덕션 빌드 후 `npm run test:performance`로 모의 Supabase와 실제 Next.js 서버를 연결해 조회 횟수, 세션 폐기, 사진 접근 권한을 검증할 수 있습니다. 실제 운영 DB에는 접근하지 않습니다. 같은 달 날짜 선택은 브라우저에서 처리하고, 사진은 열 때만 서명 URL을 발급하며, 세션 조회는 한 번의 서버 렌더 안에서 중복 제거합니다. 변경 근거와 측정 결과는 `docs/performance-refactor.md`에 기록합니다.

## 구조와 제한

- `app`: 페이지, 인증된 Server Actions, 사진 업로드·열람 라우트
- `components`: 모바일 반응형 화면과 공통 대화상자
- `lib`: 커리큘럼, 날짜, 인증, 권한과 저장 처리
- `supabase/schema.sql`: 운영 DB와 비공개 버킷 초기화
- `scripts`: 비밀번호 해시 초기화와 로컬 → Supabase 이전
- `DESIGN.md`: 디자인·접근성·반응형 기준

LMS의 진도·잠금 상태·마감일은 연동하지 않습니다. 실제 학습은 외부 LMS에서 진행하고 이 서비스에서는 계획과 인증만 관리합니다. 자동 반복, 알림, 파일 자료실, 관리자 기능은 포함하지 않습니다. 생년월일 원문은 별도로 저장하지 않습니다.

퀴즈는 `/quiz`에서 이용합니다. A-1 55개, A-2 48개, A-3 52개, A-4 45개로 구성하며 영어를 보고 한국어 뜻을 고릅니다. 문제·보기는 매번 섞고 모든 단어를 한 번씩 출제합니다. 복습은 직전 라운드에서 틀린 단어만 대상으로 하며 한 문항만 남아도 네 개의 보기를 제공합니다. 풀이 내용은 현재 페이지에서만 유지되며 페이지를 새로 열면 묶음 선택부터 시작합니다. 점수나 단어 목록은 DB에 새로 저장하지 않습니다.
